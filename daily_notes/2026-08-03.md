# Make the strand filter evidence-aware (depth + MAF)

**Proposal only — no code is to be changed by this plan without a separate go-ahead.**

## Context

The `evaluating_bronko.ipynb` analysis showed that above 2% allele frequency bronko calls 62.5% of seeded variants while iVar calls ~100%, and that **83% of the misses are rejected by the strand-odds test** (`src/call.rs:1907`). The alt allele in this data is nearly single-stranded (median 0.5% of its reads on the minority strand), so SOR lands at ~10.5 against a flat cutoff of 8 — regardless of whether the allele is supported by 9 reads or by 1,200.

That is the defect: **`--strand_odds` is a constant, but the question it is trying to answer is not.** A one-sided allele carried by a handful of reads at 0.3% is a plausible artifact. The same skew carried by 1,200 reads at 6% is not — no error process produces 1,200 concordant reads at one position. The tolerance should therefore rise with the evidence behind the allele, and it should rise _only_ when the allele is also well above the frequency range where errors live, so that deep sequencing does not license low-frequency noise.

Note what this is _not_: it is not a better statistical test of strand bias. A significance-based test (Fisher/FDR, as LoFreq uses) moves the wrong way — more depth makes a given skew _more_ significant, so the filter gets _more_ aggressive exactly where it should relax. That is visible in the same data: LoFreq's recall at 2–5% AF is 10%, worse than bronko's 60%. SOR stays as the statistic; what becomes adaptive is the **tolerance**.

Decisions already taken (from the design discussion): stringency scales on **raw AF**, and the rule is **relax-only** by default, with the low-AF tightening arm implemented but off.

## The rule

At each candidate, before the strand test:

Depth enters through `log10(a) = log10(depth) + log10(af)`, so at fixed AF a 10x deeper run buys one more `STRAND_ODDS_GAIN` of tolerance. The multiplicative `s` is what enforces "low MAF stays stringent even at high depth": below `AF_LOW` the gain is exactly zero no matter how deep the site is, which is the specific behaviour asked for.

With the recommended defaults (`GAIN 3.0`, `AF_LOW 0.005`, `AF_HIGH 0.05`, `CAP 16`):

|allele|alt reads|effective cutoff|
|---|---|---|
|0.3% AF at 300,000x|900|**8.0** — unchanged, depth buys nothing|
|0.6% AF at 17,000x|100|8.5|
|2% AF at 20,000x|400|11.9|
|6% AF at 20,000x|1,200|15.8 → capped at 16|

The optional tightening arm (off by default, `STRAND_ODDS_TIGHTEN = 0.0`) extends `s` to `[-1, 1]` and subtracts `STRAND_ODDS_TIGHTEN * min(s, 0)`, pulling the cutoff toward a floor for sub-`AF_LOW` alleles.

## What it does to the data

Measured on the 71,579 called sites in `minor_calls.csv` (798 samples), re-applying the gates to bronko's own pileup counts exactly as the notebook does. Deltas are against today's `bypass + flat 8`:

|rule|+truths ≥2%|+truths <1%|+PCR errors|+unexplained|≥2% truths clearing the strand filter|
|---|---|---|---|---|---|
|today (flat 8)|—|—|—|—|**64.6%**|
|flat 12|+762|+964|+588|+25|90.2%|
|**adaptive, GAIN 3.0, cap 16**|**+921**|**+67**|**+238**|**+2**|**95.5%**|
|adaptive, GAIN 2.0|+842|+41|+194|+2|92.9%|
|adaptive, GAIN 4.0|+923|+90|+266|+2|95.6%|

The adaptive rule **dominates the flat loosening on the axis that matters**: it recovers more high-AF truths (+921 vs +762) while admitting 2 unexplained calls instead of 25, because it declines to loosen at low AF where the flat cutoff would have. GAIN 4.0 buys nothing over 3.0 except low-AF recall.

Because gain ≥ 0 everywhere, **no variant bronko calls today is lost** — verified: zero rows flip from pass to fail. Setting `GAIN = 0` reproduces current behaviour bit for bit.

### Side finding: the `--balance-ratio` bypass stops mattering

SOR already contains `+ln(ref_ratio)`, which discounts sites whose own coverage is one-sided — the same job the bypass does, but continuously instead of as a cliff at 0.3. Under the adaptive rule, removing the bypass entirely changes the ≥2% truth count by **0** (2,845 either way) and the unexplained count by −4. Under the flat cutoff, removing it costs 677 high-AF truths. In other words the bypass is load-bearing today only because the threshold is wrong, and it is the cliff that makes the current outcome look arbitrary (94.5% recall at bypassed sites vs 22.8% at tested ones).

**Recommendation: leave the bypass in place for this change** — it is a no-op under the new rule and removing it is a separate, independently arguable change.
